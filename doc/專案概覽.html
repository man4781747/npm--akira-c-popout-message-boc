2. 互動示範（載入 lib/ 建置檔）

兩組示範都以 <script> 載入 ../lib/ 下即將發佈的 UMD 建置檔，直接用 file:// 開啟即可。訊息出現在畫面右上角。

兩個 UMD 檔各自內含一份核心，所以兩組示範的計數與上限互不影響（訊息會放進同一個容器）。這是 UMD 單檔的特性；透過 npm 以 ESM 使用時，Vue 入口直接引用 core 入口，兩者共用同一份狀態（有單元測試保護）。

core（不需要 Vue）

載入 popout-message-box-core.umd.cjs，全域 PopoutMessageBox，完全離線可用。

subscribe 收到：顯示 0 / 上限 10

Vue 3 plugin

載入 popout-message-box.umd.cjs，全域 PopoutMessageBoxVue；Vue 由 unpkg 載入（需要網路）。

status ref：顯示 {{ notify.status.count.value }} / 上限 {{ notify.status.maxItemNumber.value }}

可以觀察到：本頁 body 的 line-height: 1.7 會被訊息卡片繼承，卡片比 demo 頁高一些（見問題 3）。輸入 0 或小數到上限欄位會觸發 RangeError，錯誤訊息會顯示在面板下方。

3. 功能與 API

兩個入口

import 路徑匯出需要 Vue
akira-c-popout-message-boxdefault（{ install, usePopoutMessage }）、PopoutMessagePlugin、usePopoutMessage、notify，型別 PopoutMessageMethods 等是
akira-c-popout-message-box/corenotify，型別 PopoutMessageCore、PopoutMessageState、PopoutMessageListener、MessageType否

兩個入口的 notify 是同一個物件，Vue 專案也能在元件外（axios 攔截器、router guard 等）直接 import notify。

使用方式

// 不用 Vue
import { notify } from 'akira-c-popout-message-box/core'
notify.success('儲存成功', '資料已更新', 5)
const off = notify.subscribe(({ count, maxItemNumber }) => { /* ... */ })

// Vue
import PopoutMessagePlugin, { usePopoutMessage } from 'akira-c-popout-message-box'
createApp(App).use(PopoutMessagePlugin).mount('#app')
const notify = usePopoutMessage()   // setup() 內
notify.status.count.value           // Vue ref

DOM 結構

<div id="popout-message-box-list">            ← 容器，固定於右上角（首次顯示時建立）
  <div class="popout-message-box">            ← 單則訊息外層（新的在最上方）
    <div class="popout-card popout-card--success">
      <div class="popout-card__time-mask">     ← 倒數遮罩（懸停時加 --stop）

        <div class="popout-card__desp">補充說明</div>

樣式以 <style id="popout-message-box-style"> 在顯示第一則訊息時注入 <head>（只注入一次）。

行為一覽

  • 位置：依 position 在容器加上 popout-position--* class，支援上、下方的左、中、右六個位置（上方距頂端 3rem）；z-index: 99999，最大寬 400px，超出高度可捲動。
  • 排序與透明度：DOM 中新訊息永遠在最前面；下方位置以 flex-direction: column-reverse 讓新訊息顯示在最下面。只有最新一則不透明，其餘 opacity 0.3，懸停時恢復。
  • 不自動關閉：lifeTime（或 duration）為 0 時不計時、隱藏倒數遮罩，只能點擊或 close() 關閉。
  • 控制物件：update() 修改文字、類型、顯示時間並重新計時（懸停中則保持暫停）；內容變動後重新量測卡片高度。
  • 倒數視覺：.popout-card__time-mask 以 lifeTime 秒的 CSS 動畫由左至右填滿。
  • 懸停暫停：mouseenter 暫停計時並記下剩餘時間；mouseleave 以剩餘時間繼續（已在關閉中則不再計時）。
  • 點擊關閉：點擊卡片任何位置立即開始關閉。
  • 數量上限：顯示中的訊息超過上限時，從最舊的開始關閉。
  • 動畫：popout-slide 靠右時由右滑入、向右上滑出；靠左時方向相反；置中時改為淡入淡出；離場時收合高度，關閉 2 秒後移除 DOM。

4. 架構與運作原理

檔案職責

檔案職責
src/components/popoutMessageBox/popoutMessageCore.ts核心（不依賴 Vue）：設定（configure）、注入樣式、建立容器與訊息 DOM、進出場動畫、計時與暫停、控制物件、上限、狀態與訂閱、notify 單例
src/components/popoutMessageBox/popoutMessageService.tsVue 轉接層：訂閱核心、同步成 status 的 ref，定義 PopoutMessageMethods
src/components/popoutMessageBox/PopoutMessagePlugin.tsVue plugin：provide 服務、usePopoutMessage()
src/components/popoutMessageBox/popoutMessageBox.css樣式（巢狀 CSS，經 postcss-nesting 轉換；核心以 ?inline 載入成字串）
packages/index.ts / packages/core.tsVue 入口 / core 入口
src/App.vue、src/main.ts、index.htmlVue demo 頁面
tests/unit/、tests/e2e/Vitest 單元測試、Playwright E2E（含不使用 Vue 的 fixture 頁）

呼叫流程

重點：訊息不在使用者的元件樹裡，而是由核心直接建立在 <body> 下的獨立容器中。Vue 轉接層只是核心的一個訂閱者，因此 Vue 與非 Vue 用法共用同一套邏輯。

單則訊息的生命週期（核心內的 closure）

  1. 建立：組出 DOM 並 prepend；卡片加上 popout-slide-enter-from / -active，兩個 frame 後換成 -enter-to，transitionend 後移除。
  2. 100ms 後：若尚未關閉，把卡片高度固定為實際高度，讓關閉時的高度收合有動畫。
  3. 計時：restartCountdown(lifeTime) 設定 setTimeout(close, lifeTime * 1000) 並重播遮罩動畫（0 則不計時）；pause() 清計時並扣掉已過時間、遮罩加 --stop；resume() 以剩餘時間重新計時。
  4. 修改 update()：先驗證，再改文字、替換類型 class；若已量測過高度則重新量測，最後 restartCountdown()。
  5. 關閉 close()（時間到、點擊、或被上限擠出）：以 closing 旗標防止重複執行 → 停止計時 → 移出 openItems → 高度設 0 並播放 popout-slide-leave 動畫 → emitChange()。
  6. 2 秒後：移除外層 DOM。

模組層級狀態

  • openItems（顯示中訊息的控制物件）、listeners、config（max、duration、position）都在核心模組內，整個頁面只有一份（單例）。
  • 訊息與核心之間以 closure 與物件引用對應，不使用 DOM id、自訂事件或 uuid。
  • 載入模組時不存取 document，第一次顯示訊息時才建立 <style> 與容器。

CSS 的處理方式

6. 已知問題與待辦

高 會造成錯誤行為 中 影響使用者整合或發佈 低 清理 / 改善

中 1. Vue 版本範圍與型別不一致
package.json — peerDependencies.vue；lib/src/.../popoutMessageService.d.ts

peer 範圍是 ^3.2.41，但 Vue 入口的型別使用 Vue 3.5 才有的 Ref<number, number>。執行時沒有影響；使用 Vue 3.5 以前、且開啟型別檢查（skipLibCheck: false）的 TS 專案可能報錯。可把範圍提高到 ^3.5.0，或維持現狀並在 README 說明。core 入口不受影響。

中 2. 發佈前的 git 整理
工作區

見第 1 節：大量變更未 commit；popoutMessageBox.vue 刪除尚未 stage；.github/skills/... 為「已 staged 但已刪除」；doc/、.claude/ 是否納入版控待決定。另外 0.0.10 是從未 commit 的狀態發佈的，git 歷史中沒有對應的 commit。

低 3. 卡片會繼承頁面的 line-height 等文字樣式
popoutMessageBox.css

class 改名後已不會被同名樣式影響，但元件沒有明確設定 line-height、font-family 等可繼承屬性，會沿用使用者頁面的值（本頁示範的卡片就比 demo 頁高）。可在 #popout-message-box-list 上明確設定。

低 4. dev 指令不跨平台
package.json — dev:local、dev:built

set VAR=x&& 只在 Windows cmd 有效，macOS / Linux 需改用 cross-env。（測試與 build:lib 已改用 --mode，不受影響。）

低 5. 時間常數與 CSS 重複
popoutMessageCore.ts — REMOVE_DELAY = 2000；popoutMessageBox.css — transition: all 0.5s

核心假設離場動畫在 2 秒內結束。若使用者以 CSS 把動畫改得比 2 秒長，DOM 會在動畫結束前被移除。

低 6. status 的 ref 可被寫入但不會生效
popoutMessageService.ts

status.count / status.maxItemNumber 是一般 ref，寫入後只會改到 ref 本身，不會影響核心（下一次狀態變化時會被覆蓋）。README 已註明「唯讀用途」，可考慮改成 readonly()，但會改變型別。

低 7. UMD 副檔名 .cjs 在部分 CDN 無法用 <script> 載入
lib/*.umd.cjs

unpkg 回傳 text/javascript 可正常使用（README 範例使用 unpkg）；jsDelivr 回傳 application/node 並帶 nosniff，瀏覽器會拒絕執行。若要支援 jsDelivr，需另外輸出 .js 副檔名的 UMD（但 "type": "module" 下 .js 會被 Node 當成 ESM，require 仍需 .cjs）。

低 8. vite-plugin-dts 已不建議使用
vite.lib.config.js

其 README 建議改用 unplugin-dts；目前版本只是包裝 unplugin-dts，功能正常。

後續可改善的方向（非問題）

  • notify.promise(p, { loading, success, error })、相同訊息合併、動作按鈕。
  • 無障礙：aria-live、error 使用 role="alert"、Esc 關閉、prefers-reduced-motion。
  • 主題：以 CSS 變數自訂顏色（目前 info 為固定色）、深色模式。
